# ADR-0006: Staging infrastructure choices
**Status:** accepted as *configuration prepared, nothing provisioned.* Render (API, worker, Key Value, private ClamAV), Neon (Postgres + pgvector later), Cloudflare R2 + Workers Static Assets, Auth0. Business logic has no vendor coupling beyond environment variables; the container runs anywhere.
- **Redis:** Render Key Value is Redis-compatible; the app uses only `EVAL`, hashes, sorted sets, `GETDEL` (Redis ≥ 6.2). Use TLS (`rediss://`) when available. Verify `GETDEL` support on the chosen version.
- **Neon:** use the pooled endpoint for `vand_app`/`vand_worker` with `VAND_DB_DISABLE_STATEMENT_CACHE=true`; the direct endpoint for migrations as `vand_owner`. Startup refuses a role that is superuser/BYPASSRLS/owns tenant tables. Neon roles created via the console are `neon_superuser` members by default — **create `vand_app`/`vand_worker` as plain roles via SQL (`infra/database/roles.sql`) and run the unsafe-role check in staging.**
- **R2:** private bucket, scoped API token (Object Read/Write on one bucket), no public access/custom domain; adapter verified only against an S3 emulator.
- **Edge:** Worker proxies `/api/*` with `X-Origin-Auth`; API rejects non-edge traffic. Cloudflare WAF managed rules, rate-limiting rules on `/api/v1/auth/*`, Bot Fight/Turnstile on the login redirect are **dashboard configuration not performed**. Restrict the Render origin by IP is not possible on all plans; the shared secret is the control.
- **pgvector:** Neon supports `CREATE EXTENSION vector`; enable in a later migration (`0003`) with HNSW indexes, tenant column included in queries. Local image prepared at `infra/local/docker-compose.yml`. No vector work is done in this phase.
